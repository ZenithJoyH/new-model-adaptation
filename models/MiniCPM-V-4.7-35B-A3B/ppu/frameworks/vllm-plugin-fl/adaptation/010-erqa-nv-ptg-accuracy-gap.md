## 问题现象与原始证据

均位于 Host 工作根 `/mnt/nfs/users/jinghao/MiniCPMV4.7-35B/`，
各含相同顺序、相同文本问题的 400 个唯一 ID。文件和公开
[FlagEval/ERQA](https://huggingface.co/datasets/FlagEval/ERQA)
标注修订、逐题对齐方法、SHA-256 及完整统计见
[诊断报告](../acceptance/erqa-nv-ptg-comparison-20261003.md)。

最终独立 `Answer: [A-D]` 行在 NV 395/400、PPU 400/400 题可提取。
按 400 题完整分母、请求错误计 0，NV 213/400，PPU 198/400，
差 15 题。两端答案相同 330 题，NV 独对 30、PPU 独对 15；
仅 PPU 正确的 15 题中有 3 题属于 NV `RetryError ... TypeError`
而无答案的请求。仅对两端都正常响应的 395 题诊断重算，
NV 213/395、PPU 195/395，差 18 题。PPU 没有无效最终答案或
Unicode 替换字符，完成 token 中位数与 NV 接近，故本次不是
后半段大面积生成乱码的同一签名。

## 诊断与假设

- 已验证：用户文件的 400 个文本问题逐题一致；公开标准答案按
  ID 全覆盖。374 题剔除评测指令/图标记后文本一致、20 题只差
  图标记空白、6 题评测 prompt 在公开题干后补充选项；后 6 题
  两端答案完全一致且各对 4 题，不影响分差。
- 已验证：八个公开题型中 PPU 各少对 1–3 题；单图题少对 12、
  双图题少对 5。NV 的 5 个请求错误均为三或四图题；PPU 在
  其中 3 题正确。PPU 另有 15 题 `reason` 字段为空，
  但 `answer` 含完整推理和最终字母，其中 7 题正确；
  这不是本次分差的答案提取原因。
- 已验证：MiniMax-M3.1 留存的公开 ERQA 图片清单在 PPU-13 模型容器内
  可直接读取，630/630 图片 SHA 与清单一致；用该清单复测时，
  400/400 的 prompt token 数与历史 PPU 文件逐题一致。
- 已验证：当前 PPU 与现存 H100-149 FlagOS 容器中的模型配置、
  生成配置、tokenizer 配置和权重索引哈希一致；当前 H100 原生
  8020 的生成配置、M-RoPE 参考文件，以及双方 vLLM 4.6 视觉模型
  与 Idefics2 视觉注意力源码哈希一致。权重处理器代码和预处理配置
  两端逐文件哈希一致。视觉/merger 张量所在的两个 shard 在两端
  逐字节 SHA-256 一致；其他权重 shard 和历史服务实例仍未核实。
- 源码只读对照：H100-149 当前 Plugin 的 4.7 adapter 位于
  `/vllm-workspace/vllm-plugin-FL/vllm_fl/models/minicpmv4_7.py`
  （SHA-256 `2e96de24dc2aa003ed21b146e602102bf9ee30ca075dfe6a8986cb45b006213e`）；
  PPU Plugin 位于 `/workspace/vllm-plugin-FL/vllm_fl/models/minicpmv4_7.py`。
  两者均使用 4.6 视觉 processor、Qwen3.5 MoE 文本和 checkpoint
  canvas M-RoPE。PPU 额外绑定窗口合并后 FP32 视觉注意力。
  NV 显式按特征 offset 排序，PPU 未排序；其是否在实际
  `mm_features` 顺序上产生差异尚未测得，且单图题净差仍占多数。
  PPU 对 merger 显式传入的 `(2,2)` / `times=1` 与
  vLLM 默认一致；参考 M-RoPE 函数会把 PPU 传入的二维 bounds/sizes
  自动包装为单 batch，tokenizer 四个图像标记也与 NV 写法一致。
  此静态对照未发现可直接解释全量分差的模型语义错误。
- 已验证：当前 H100 评测容器已有 ERQA 630 张图片；与 PPU 所用
  630 张图片逐题逐张 SHA 一致。当前两端 400 题全文聚合摘要与
  实际 prompt token 聚合摘要均相同。历史 NV/PPU 文件仍缺少图片
  哈希、完整客户端请求和服务修订，不能倒推历史单轮的输入身份。
- 待验证：首个跨平台数值分歧、视觉目标尺寸/位置编码的实际张量、
  完整权重 shard，以及同题跨平台重复运行的方差。

真实图片、固定 45 题图/eager 贪心对照和图模式 400 题复测的

13/45 题的正确性发生翻转；全部 45/45 prompt token 数吻合
历史 PPU 文件。单题 `ERQA_165`：贪心、同图片、相同 590 个
prompt token，图模式并发 20 在两次实例中分别 4/20 与 1/20
答标准答案 A，eager 并发 20 为 0/20，图模式串行为 0/20。
这支持图服务的批处理敏感性，但未证明它导致全量净分差。

完整 400 题诊断用模型生效默认采样
`temperature=1,top_p=0.95,top_k=20`、并发 32、
`max_tokens=32768`、不重试；400/400 正常停止、0 错误、
0 无效答案，得 **200/400**。与历史 PPU 198/400

因此本轮是复现性诊断，不是 profile 正式回执，也不能视为

与第一次 200/400 相比 82 题最终选项翻转。H100 当前 8020

`ERQA_165` 是明确的单题跨框架差异：相同题干 SHA、图片 SHA、

这排除前段后端切换作为该单题的直接修复；不解释
400 题全量稳定差距。原启动参数已恢复并验证 `/health` 200。

## 根因与处理

已验证根因：无。现有证据排除了标准答案映射、末行答案提取、
大面积乱码、当前两端输入和基础模型/处理器源码身份不一致；
发现当前图服务的同题并发贪心输出会变动，且 PPU 全量得分
复测接近原分。历史 15 题净差没有在同图同参数复测中重现。
单题 `ERQA_165` 可复现不同偏向，但首个视觉/文本张量数值分歧
尚未定位。候选原因包括批量数值差异被推理链放大、
平台数值误差和采样波动；均保持 `hypothesis`。
没有支持生产 Plugin 源码修改的受控首个分歧证据，本轮未
改 Plugin、vLLM、FlagGems 或根级启动脚本。

## 验证结果、限制与下一步

当前图服务已恢复原参数并通过 `/health`，适配容器始终运行。
仅完成诊断，不能声明正式 ERQA 验收通过或已修复低分，
也不改 `framework.yml`。要把候选变成可修复的根因，
下一步需比较 `ERQA_165` 的两端视觉特征、实际 canvas
位置编码和第一个分歧 token，再用更多同图同参数重复轮确认
400 题是否有稳定差距。NV 的 5 个历史 `TypeError` 请求
应单列，不从分母删除。任何确定的算子故障再按 profile
放入 `07-bugs/` 并覆盖 eager/graph 验证。

经验沉淀：`local-only`；当前结论不推广为跨模型、跨平台修复方案。
