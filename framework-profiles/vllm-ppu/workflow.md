# 平头哥原生 vLLM 适配工作流

本 experimental profile 只适用于用户指定的 PPU 原生 vLLM 安装；继承
[通用适配政策](../../docs/adaptation-policy.md)和[远程操作边界](../../docs/remote-operations.md)。
不继承 Plugin、FlagGems 或 NVIDIA 源码树的写入授权。

1. 写入前验证 Host、容器、镜像、工作根及挂载映射、解释器、包元数据和实际导入路径。
   修改实际安装的 vLLM Python 产品代码，支持普通 wheel 安装和 editable 来源；先记录文件
   SHA/Git 身份、已有差异并备份。禁止建立另一份源码或用 PYTHONPATH 选择替代实现。
2. 权重、模型仓库内的配置与处理器、驱动、PyTorch 和原生内核保持只读。需要二进制修复时，
   先确认授权的真实构建源码与该组件自身安装过程；缺失时停止该部分，不能直接覆盖共享库。
3. 使用正常模型 registry、多模态 processor、权重 loader、模型专用位置编码与语言骨干接口。
   先记录未修改代码的失败，再作必要修改；不在公共调度热路径按模型名称分支。
4. 先验证导入、注册、配置、token/位置与权重映射，再跑真实权重 eager，然后验证 graph。
   覆盖文本、图像、模型声明的视频、批处理和前缀缓存；新模型专用改动不应改变已有模型路径。
5. 图模式按 full → full-and-piecewise → decode-full → piecewise 检查；降级前记录上一级
   失败、定位与修复尝试。用户已指定图模式时保留其要求，明确实际生效覆盖，不用自动降级冒充成功。
6. 仅操作当前任务服务，保持容器运行。一次性脚本、备份、缓存与结果放在批准根的标准子目录，
   产品安装目录只保留必要产品实现及可维护测试。完成时审查实际文件增量和未验证范围。

本 profile 尚未建立完整正式精度、性能验收接口，不能据局部验证签发完整验收或 optimized 状态。
